# 設計・費用・制約

## データの流れ

スタッフ → 共通ログイン → Workers API → Twitch公式API → R2 → D1一覧 → 編集 → 公開スナップショット → OBS。
保存期限 → Cron（1分ごとに1件を1段階処理）→ Drive転送 → DriveのID・容量を確認 → D1に保存確認記録 → R2削除 → アーカイブ済み。

動画を編集するたびに変換せず、開始秒・終了秒・並び順・PNGのIDを保存します。OBSには保存中の下書きを渡しません。フレームの追加は新規IDです。差し替えには選び直しと再公開が必要です。

## Twitchの仕様

2026-10-14に [公式API Reference](https://dev.twitch.tv/docs/api/reference/#create-clip) を確認。通常のCreate Clipはduration=5〜60秒（0.1秒精度）を受け付けます。初期値は60秒を要求し、実際に返ったdurationを採用します。配信開始・終了付近では短くなります。視聴遅延はアプリから測定できないため「ボタン直前の正確な60秒」は保証できません。

必要な権限は `clips:edit`（作成）と `channel:manage:clips`（nobori_official本人の動画取得）。スタッフ全員のTwitchログインは不要です。公式ダウンロードAPIを使い、サムネイルURLの書き換え・スクレイピングは行いません。取得APIは100回/分の独自上限があります。生成確認は最大60秒の目安で実行します。

## アーカイブの安全性

処理中のクリップに90秒の期限付きロックを設定し、他の処理が同時取得できないようにします。90秒を超えるネットワーク停止時は回復できますが、外部処理の遅延がそれを超える状況は本番検証が必要です。

DriveファイルIDを先に確保し、再試行でも同じIDを使用します。転送先セッションURLは暗号化して保存します。毎回Driveの受信済み位置を確認して、4MB分だけストリーム転送します。全動画をメモリに読み込みません。完了後に別のAPIでファイルID・容量・ゴミ箱状態を確認します。R2とDriveの双方がMD5を返した場合は照合します。

Drive保存確認をD1に記録した後にR2を削除します。途中で失敗した場合は元動画を残します。R2削除後・D1完了前の中断では、前回の保存確認記録とDriveの再確認を使って完了状態に回復します。Driveの無関係なファイルを削除・上書きするAPIは用いません。

再生リストで使用中、公開中、OBS再生中の素材は期限を過ぎても転送を保留します。下書きからも外すと転送対象に戻ります。OBSの再生保護は定期的に90秒まで延長します。長い通信断では保護延長もできないため、ブラウザキャッシュだけで再生継続を保証しません。

復元はDriveのファイルを保持したままR2へコピーし、再利用期限を24時間後に設定します。再度のアーカイブ時には同じDriveファイルの容量を検証します。

## Googleの権限と保存先

`drive.file` を使用。本アプリが作ったファイルのみ操作できます。管理者の既存のDrive全体にアクセスしません。初回に「NOBORI Highlight Studio」フォルダを作成し、`日付_タイトル_クリップID.mp4` で保存します。シーズン別サブフォルダは今後の追加候補です。

同じGoogleアカウントの再接続を想定します。アカウントを変更した場合はフォルダへのアクセスがなく、転送エラーになり元動画を保持します。アプリ上のアーカイブ本数はD1に記録したものです。一覧は48件ずつページ表示し、タイトル・タグ検索はサーバー側で全クリップを対象にします。個人Drive全体の容量・他のファイルの使用量を示す数値ではありません。

## セキュリティー

パスワード・PINは平文保存せず、Cloudflare Secretのランダム鍵によるHMAC-SHA256で照合します。D1だけが流出しても鍵なしではオフライン照合できません。鍵は十分な強度で生成し、公開・使い回しを避けます。OAuth情報は別のAES-256-GCM鍵で暗号化します。

12時間のHttpOnly・Secure・SameSite=Lax Cookie、Origin照合、セッションごとのCSRFトークン。ログインは接続元IPを鍵付きハッシュに変換して15分8回まで、PINはセッションと接続元IPの双方で15分8回まで。成功したPINは回数を解除します。共通パスワード変更で全セッションを失効します。OBSは別の署名トークンで管理APIに入れず、再発行で旧URLを失効できます。

任意の表示名は本人確認ではありません。ログにはIPそのものや秘密情報を保存しません。操作ログを90日で削除します。秘密情報をGitHub・チャット・フロントエンドへ出さないでください。

## 月額0円について

**0円は目標で、保証できません。R2の有効化には支払い方法の登録を求められる場合があります。** 以下は2026-10-14に確認した公式資料の条件です。最新の契約画面を優先してください。

| 項目           | 無料枠・制限                                                           | 超過時と対策                                                                                                        |
| -------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Workers Free   | 10万リクエスト/日、HTTP・CronともCPU 10ms、128MB                       | Freeの上限で失敗する場合があります。有料プランへ自動で変更しない                                                    |
| R2 Standard    | 月10 GB-month、Class A 100万回、Class B 1000万回                       | 超過分に料金。アプリは初期8 GiB上限で停止を目標にし、並行取り込み分も予約計算。R2全体・操作回数には強制課金停止なし |
| D1 Free        | 1日読取500万行・書込10万行、アカウント合計5GB                          | 上限で失敗。検索・ポーリングの頻度と保持データ数に注意                                                              |
| Drive          | ユーザー契約の空き容量を利用                                           | 既存の2TB契約費用はこのアプリの追加費用に含めない。API・アップロードの制限で保留・再試行                            |
| GitHub Actions | 公開リポジトリは標準ランナーの無料条件あり。非公開は契約の無料時間まで | 不要なPushを減らし、無料時間と支出上限を確認                                                                        |

R2の読み取りは動画のRange要求・先読み・再試行ごとに増えます。他のR2バケットと無料枠を共有します。8GiBの制限はDBに記録した動画・PNGだけを計算し、孤立ファイルや他アプリ分を把握できません。容量予約の同時実行時の厳密な上限には未対応なので、低い上限で余裕を持ってください。

1分Cronでは1回につき4MBまでなので、単純計算で最大約240MB/時。初期化・確認・失敗の分だけ遅くなります。大量素材では期限当日の即時移動は保証できません。無料CPU 10ms内で実行できるか、本番Metricsを見て判定してください。超過した場合に有料サービスへ勝手に変更しません。

## API拡張と今後

`POST /api/clips` はrequestKey（UUID）で同じ要求の重複を防ぎます。Chrome拡張も同じ保存処理を使います。通常WebのCookie・Origin・CSRF制約は維持し、拡張には`/api/extension/`専用の限定トークンを発行します。

## Chrome拡張（NOBORI Clip）

Manifest V3のサービスワーカーから専用APIへ通信します。Twitchの全ページで軽いスクリプトを起動してSPA移動を検知しますが、パネルと保存操作はnobori_officialのチャンネルページだけで有効です。Twitchの動画・チャット・Cookieは読み取りません。通信先はAPP_ORIGINに対応する固定の本番ホストのみです。

アプリでログイン・CSRF確認後に5分有効のコードを発行し、拡張ポップアップから一度だけ引き換えます。コードはDELETE RETURNINGで原子的に消費します。コードとBearerトークンはD1へSHA-256ハッシュだけを保存します。トークンは親のログインセッションへ結び付け、期限・credential_epoch・ログアウトを毎回検証します。専用APIは保存、保存処理の続行、最近5件の状態確認、自分のトークン解除だけを受け付けます。編集・管理・素材読取には利用できません。

Chromeのstorage.sessionに認証情報を置き、session/local両方のアクセスレベルをTRUSTED_CONTEXTSへ制限します。コンテンツスクリプトへトークンを返しません。コンテンツスクリプトのメッセージは送信元ID、公式チャンネルURL、トップフレームを検証し、コード引換と解除は拡張自身のポップアップだけへ許可します。任意URLの代理取得やページからのwindowメッセージ受付は用意しません。

要求IDと保存内容は応答が確定するまでlocalへ保持し、ワーカー休止・通信切断でも同じ内容で再試行します。サービスワーカー内の同時保存もまとめます。処理中は5秒、通常は30秒で最近の状態を確認し、非表示タブ・折りたたみ・別チャンネルでは定期通信を止めます。Chrome拡張の読み込み手順は[extension/README.md](../extension/README.md)を参照してください。
